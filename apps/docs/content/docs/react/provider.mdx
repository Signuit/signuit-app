`NexusProvider` is **not a standalone component you import** — it is a property on the `nexus` instance returned by `createNexusClient()`. This design (inspired by [better-auth](https://better-auth.com)) means the provider is always bound to the exact client instance that created it, with no mismatched context.

```ts
// 1. Create the client
const nexus = createNexusClient({ baseUrl: '...', plugins: [...] });

// 2. Use the bound provider — it knows about this nexus instance
<nexus.NexusProvider>
  {children}
</nexus.NexusProvider>

// 3. Hooks also come from the same instance — zero context lookup
nexus.useContracts(...)
nexus.useCreateContract(...)
```

## Custom QueryClient

Pass a `QueryClient` to control caching behavior globally. Create it **outside** the component (module-level) to prevent re-creation on every render:

```tsx title="components/providers.tsx"
'use client';

import { QueryClient } from '@tanstack/react-query';
import { nexus } from '@/lib/nexus-client';

// Canton finality is typically 3–10 seconds — staleTime of 5s is a good default
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5_000,
      retry: 2,
      retryDelay: (attempt) => Math.min(1000 * 2 ** attempt, 10_000),
      refetchOnWindowFocus: true,
    },
    mutations: {
      retry: 0, // don't retry failed ledger commands
    },
  },
});

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <nexus.NexusProvider queryClient={queryClient}>
      {children}
    </nexus.NexusProvider>
  );
}
```

## Multiple parties

Each `createNexusClient()` call produces its own isolated `NexusProvider` with its own TanStack Query cache. Use this for multi-party UIs (e.g. a demo showing both institution and counterparty views simultaneously):

```ts title="lib/clients.ts"
'use client';

import { createNexusClient, authPlugin, tanstackQueryPlugin } from '@nexus-framework/react';

// VantageCapital (institution) view
export const institutionNexus = createNexusClient({
  baseUrl: '/api/ledger',
  plugins: [
    authPlugin({ basePath: '/api/nexus-auth/institution' }),
    tanstackQueryPlugin(),
  ],
});

// PrimeBank (counterparty) view
export const counterpartyNexus = createNexusClient({
  baseUrl: '/api/ledger',
  plugins: [
    authPlugin({ basePath: '/api/nexus-auth/counterparty' }),
    tanstackQueryPlugin(),
  ],
});
```

```tsx
<institutionNexus.NexusProvider>
  <counterpartyNexus.NexusProvider>
    {children}
  </counterpartyNexus.NexusProvider>
</institutionNexus.NexusProvider>
```

Each provider is scoped to its own session — `institutionNexus.useContracts()` only sees VantageCapital's contracts, `counterpartyNexus.useContracts()` only sees PrimeBank's.

## SignUIT setup

In SignUIT, `NexusProvider` wraps the entire app in the TanStack Start root route. The `nexus` client uses `authPlugin()` pointing at `/api/nexus-auth`, which in turn routes to `createAuthHandler()` on the server:

```tsx title="apps/web/src/routes/__root.tsx"
import { nexus } from '@/lib/nexus-client';

// nexus-client.ts:
// export const nexus = createNexusClient({
//   baseUrl: '/api/ledger',
//   plugins: [authPlugin({ basePath: '/api/nexus-auth' }), tanstackQueryPlugin(), nexusTypes],
// });

export const Route = createRootRoute({
  component: () => (
    <nexus.NexusProvider>
      <Outlet />
    </nexus.NexusProvider>
  ),
});
```

See [React: Setup](/docs/react/setup) for the full `nexus-client.ts` setup and [Core: Server](/docs/core/server) for the server-side auth wiring.
