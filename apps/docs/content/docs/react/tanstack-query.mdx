`tanstackQueryPlugin()` is what turns the `nexus` client into a React-ready data layer. Without it, `nexus` can talk to Canton but has no hooks. With it, every contract on the ledger is a TanStack Query-powered reactive state object in your UI.

---

## Add it to your client

```ts title="lib/nexus-client.ts"
import { createNexusClient, authPlugin, tanstackQueryPlugin } from '@nexus-framework/react';
import { nexusTypes } from './nexus-types';

export const nexus = createNexusClient({
  baseUrl: '/api/ledger',
  plugins: [
    authPlugin({ basePath: '/api/nexus-auth' }),
    tanstackQueryPlugin(), // [!code highlight]
  ],
  types: nexusTypes,
});
```

Once added, the following are available on `nexus`:

- `nexus.useContracts()`
- `nexus.useContractsSuspense()`
- `nexus.useInterface()`
- `nexus.useCreateContract()`
- `nexus.useExerciseChoice()`
- `nexus.useExerciseAndGetResult()`
- `nexus.useLedgerMutation()`
- `nexus.usePartyId()`
- `nexus.useLedgerEnd()`
- `nexus.useSynchronizers()`

If you have `nexusTypes` registered as well, `nexus.types.X.*` versions of all hooks are also available with full type inference.

---

## How caching works

Canton ledger finality typically takes 3–10 seconds. The plugin uses a default `staleTime` of 5 seconds — data is served from cache immediately, but a background refetch runs once it's older than 5 seconds. This gives you a balance between freshness and performance.

**Mutations automatically invalidate related caches.** After `useCreateContract` or `useExerciseChoice` succeeds, any `useContracts` call for the affected template will refetch in the background. You never call `invalidateQueries` manually.

If a choice creates contracts of a different template (like `ApproveSuggestion` creating an `AllocationRecord`), pass `invalidateTemplates` to invalidate both:

```tsx
const { mutate } = nexus.useExerciseChoice({
  invalidateTemplates: [
    'nexus-example-0.0.1:CollateralRouter:RoutingSuggestion',
    'nexus-example-0.0.1:CollateralRouter:AllocationRecord', // Also invalidated
  ],
});
```

## Custom QueryClient

By default, the plugin creates a `QueryClient` with Canton-friendly defaults. Override it by passing your own to `NexusProvider`:

```tsx
import { QueryClient } from '@tanstack/react-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 10_000,    // 10s — if your app can tolerate slightly older data
      retry: 2,
      refetchOnWindowFocus: true,
    },
    mutations: {
      retry: 0, // Never retry a failed ledger command — side effects may have occurred
    },
  },
});

<nexus.NexusProvider queryClient={queryClient}>
  {children}
</nexus.NexusProvider>
```

## SSR prefetch

Pre-populate the TanStack Query cache on the server so that components render without a loading state. The cache is transferred to the client via `HydrationBoundary`.

<Tabs items={["TanStack Start", "Next.js"]}>
  <Tab value="TanStack Start">
  ```tsx title="src/routes/dashboard/index.tsx"
  import { contractQueryOptions } from '@nexus-framework/react';
  import { createServerNexusClient } from '@nexus-framework/react/server';
  import { dehydrate, HydrationBoundary, QueryClient } from '@tanstack/react-query';
  import { createFileRoute } from '@tanstack/react-router';
  import { createServerFn } from '@tanstack/react-start';
  import { CollateralList } from './-components/CollateralList';

  const loadContracts = createServerFn({ method: 'GET' }).handler(async ({ request }) => {
    const client = await createServerNexusClient({
      request,
      config: { ledgerApiUrl: process.env.CANTON_API_URL! },
    });

    const queryClient = new QueryClient();
    await queryClient.prefetchQuery(
      contractQueryOptions({
        client,
        templateId: 'nexus-example-0.0.1:CollateralRouter:CollateralHolding',
      })
    );

    return { dehydratedState: dehydrate(queryClient) };
  });

  export const Route = createFileRoute('/dashboard/')({
    loader: () => loadContracts(),
    component: function DashboardPage() {
      const { dehydratedState } = Route.useLoaderData();
      return (
        <HydrationBoundary state={dehydratedState}>
          <CollateralList /> {/* useContracts() reads from cache — no loading state */}
        </HydrationBoundary>
      );
    },
  });
  ```
  </Tab>

  import { contractQueryOptions } from '@nexus-framework/react';

      })
    );

    return (
      <HydrationBoundary state={dehydrate(queryClient)}>
        <CollateralList /> {/* Renders immediately — data is in the cache */}
      </HydrationBoundary>
    );
  }

## Cache key structure

Every hook uses a predictable, hierarchical key structure. Use `nexusKeys` when you need to invalidate specific parts of the cache manually:

```ts
import { nexusKeys } from '@nexus-framework/react';
import { useQueryClient } from '@tanstack/react-query';

const queryClient = useQueryClient();

// Invalidate all contracts for one template
queryClient.invalidateQueries({
  queryKey: nexusKeys.contractsByTemplate('nexus-example-0.0.1:CollateralRouter:CollateralHolding'),
});

// Invalidate everything Nexus Framework has cached
queryClient.invalidateQueries({ queryKey: nexusKeys.all() });
```

Full key hierarchy:

```
['nexus']
['nexus', 'contracts']
['nexus', 'contracts', templateId]
['nexus', 'contracts', templateId, filters]
['nexus', 'interfaces', interfaceId]
['nexus', 'ledger-end']
['nexus', 'party', userId]
```
