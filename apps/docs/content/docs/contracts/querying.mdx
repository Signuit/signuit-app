<Callout type="info">
  If you have registered `nexusTypes`, you never need to call these APIs directly. Use `nexus.types.CollateralHolding.useContracts()` — no templateId string, no generic type parameter. See [Typed Namespaces](/docs/react/typed-namespaces).

  The APIs documented here are the underlying layer. They are useful when building your own plugins, working without Daml codegen, or calling Canton from a non-React environment.
</Callout>

The Canton ledger maintains an **Active Contract Set (ACS)** — a live snapshot of every contract that currently exists. When a contract is created it enters the ACS; when it is archived it leaves. Nexus Framework wraps the `POST /v2/state/active-contracts` endpoint with Zod validation and full TypeScript generics.

---

## React: useContracts

The TanStack Query hook for querying ACS contracts. Results are cached, refetched in the background when stale, and invalidated automatically after related mutations.

```tsx
const { data, isLoading } = nexus.useContracts<{ owner: string; amount: string }>({
  templateId: 'my-package:Module:Template',
  parties: [partyId],  // optional — defaults to the party from your auth plugin
  staleTime: 5_000,    // optional — ms before a background refetch runs
  fetchAll: false,     // optional — if true, follows all pagination cursors
});

// data.contracts: ActiveContract<{ owner: string; amount: string }>[]
// data.nextPageToken?: string — undefined means you are on the last page
```

`useContracts` checks the cache first, serves immediately, then refetches in the background once the data is older than `staleTime`.

### Fetch all pages

```tsx
const { data } = nexus.useContracts({ templateId: '...', fetchAll: true });
```

<Callout type="warn">
  `fetchAll: true` loads every page in sequence before returning. On large ledger states with thousands of contracts, this is slow and memory-intensive. For those cases, use `streamingPlugin` + `useStreamContracts` for live data, or PQS for read-heavy dashboards.
</Callout>

## Server-side: fetchActiveContracts

For scripts, background workers, or any server-side code that needs to read contracts outside of a React component:

```ts
const page = await nexus.ledger.contracts.fetchActiveContracts<{ owner: string; amount: string }>({
  templateId: 'my-package:Module:Template',
  parties: ['Alice::122059...'],
  pageSize: 100,
});

// page.contracts — typed array
// page.nextPageToken — cursor for the next page, undefined means last page

// Follow all pages automatically
const all = await nexus.ledger.contracts.fetchAllActiveContracts({ templateId: '...' });
```

## Fetch by ID

```ts
const contract = await nexus.ledger.contracts.fetchContractById<PayloadType>(
  'my-package:Module:Template',
  contractId,
);
// Returns undefined if the contract has been archived or does not exist
```

## Fetch by predicate (key lookup)

The client-side equivalent of Daml's `fetchByKey`:

```ts
const contract = await nexus.ledger.contracts.fetchContractByKey<PayloadType>(
  'my-package:Module:Template',
  (payload) => payload.owner === partyId && payload.currency === 'USD',
);
```

This fetches all contracts and filters client-side. If the template has a large ACS, prefer PQS for predicate-based lookups.

## ActiveContract shape

```ts
interface ActiveContract<T> {
  contractId:  string;       // Changes on every create — use as React key
  templateId:  TemplateId;   // { packageId, moduleName, entityName }
  payload:     T;            // The Daml template fields, typed via your generic
  createdAt:   string;       // ISO 8601 timestamp
  signatories: string[];     // Parties that authorized the creation
  observers:   string[];     // Parties that can read but not act
}
```

## SignUIT example

With `nexusTypes` registered, no generic or templateId is needed:

```tsx title="components/CollateralTable.tsx"
import { nexus } from '@/lib/nexus-client';

export function CollateralTable() {
  // nexusTypes registered — one line, fully typed, no strings
  const { data } = nexus.types.CollateralHolding.useContracts();

  return (
    <table>
      <tbody>
        {data?.contracts.map((c) => (
          <tr key={c.contractId}>
            <td>{c.payload.assetId}</td>
            <td>{c.payload.quantity} {c.payload.currency}</td>
            <td>{c.payload.custodian}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
```

When a query runs without specifying `parties`, Canton uses the party embedded in the current auth token. VantageCapital's session returns VantageCapital's contracts. The operator's session returns contracts where the operator is a signatory or observer. The scoping happens at the Canton level — no application-layer filtering needed.
