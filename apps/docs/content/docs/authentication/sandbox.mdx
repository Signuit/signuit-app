`sandboxAuth` generates signed JWT tokens that Canton Sandbox's built-in authenticator accepts. No key infrastructure, no OAuth setup, no token endpoint — you give it a secret and a party ID and it handles everything else automatically.

<Callout type="warn">
  `sandboxAuth` is for development only. The HMAC secret goes directly into your app bundle. For production, use [`jwtAuth`](/docs/authentication/jwt) or [`oidcAuth`](/docs/authentication/oidc).
</Callout>

## Server-side usage

Use `createNexus` from `@nexus-framework/core` for scripts, background workers, and server-side code:

```ts title="lib/nexus.ts"
import { createNexus, sandboxAuth } from '@nexus-framework/core';

export const nexus = createNexus({
  ledgerApiUrl: 'http://localhost:7575',
  plugins: [
    sandboxAuth({ // [!code highlight]
      secret: process.env.SANDBOX_SECRET ?? 'secret', // must match Canton's --auth-secret // [!code highlight]
      userId: 'alice',
      partyId: 'Alice::122059a10c...',
    }),
  ],
});
```

All `nexus.ledger.*` calls will automatically attach a fresh signed token — no manual `getToken()` needed.

## React client usage

For a React app, use `createNexusClient` from `@nexus-framework/react`. In production you would use `authPlugin` instead, but for local sandbox development `sandboxAuth` is simpler:

```ts title="lib/nexus-client.ts"
import { createNexusClient, sandboxAuth, tanstackQueryPlugin } from '@nexus-framework/react';
import { nexusTypes } from './nexus-types';

export const nexus = createNexusClient({
  baseUrl: 'http://localhost:7575', // direct to Canton — no server proxy needed // [!code highlight]
  plugins: [
    sandboxAuth({ // [!code highlight]
      secret: process.env.VITE_SANDBOX_SECRET ?? 'secret',
      userId: process.env.VITE_SANDBOX_USER_ID ?? 'alice',
      partyId: process.env.VITE_SANDBOX_PARTY_ID ?? 'Alice::...',
    }),
    tanstackQueryPlugin(),
  ],
  types: nexusTypes,
});
```

## Get your partyId

Query the Canton Sandbox admin API:

```bash
curl http://localhost:7575/v2/admin/parties | jq '.parties[] | select(.isLocal) | .partyId'
```

Or start the sandbox with a deterministic party hint:

```bash
docker run -p 7575:7575 \
  -e CANTON_SANDBOX_USER=alice \
  digitalasset/canton-sandbox:latest
```

## Token format

Each token is an HMAC256-signed JWT with this payload:

```json
{
  "sub": "alice",
  "aud": "https://daml.com/ledger-api",
  "scope": "daml_ledger_api",
  "actAs": ["Alice::122059a10c..."], // [!code highlight]
  "readAs": ["Alice::122059a10c..."], // [!code highlight]
  "exp": 1735689600
}
```

The `actAs` and `readAs` claims are what Canton uses to scope the request to the right party. Without them, Canton rejects the request.
