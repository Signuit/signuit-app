This guide walks through a complete Nexus Framework setup from scratch. By the end you'll have a working server, a typed browser client, and a live contract query — with no templateId strings and no generic type parameters anywhere in your components.

## Install

```bash
bun add @nexus-framework/core @nexus-framework/react @tanstack/react-query
```

---

## Step 1 — Wire up the server

The browser client never talks to Canton directly. All requests go through two server endpoints you mount:

- **`/api/nexus-auth`** — handles login, logout, session reads, and token refresh
- **`/api/ledger`** — proxies authenticated requests from the browser to Canton

Create your server module:

```ts title="lib/nexus-server.ts"
import { createNexusServer, createAuthHandler, SessionManager } from '@nexus-framework/core/server';

// Encrypts session cookies with AES-GCM.
// Generate the key once: bun -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
export const sessionManager = new SessionManager({
  encryptionKey: process.env.SESSION_ENCRYPTION_KEY,
  ttlMs: 2 * 60 * 60 * 1000, // 2 hours
  secure: process.env.NODE_ENV === 'production',
});

// Creates the Canton HTTP client, session layer, and party resolver in one call.
export const nexus = await createNexusServer({
  auth: {
    secret: process.env.SANDBOX_SECRET ?? 'secret',
    // Resolves per-request userId from the session cookie.
    // This is what makes each request scoped to the right Canton party.
    getUserId: (ctx) => ctx.session?.userId,
  },
  session: sessionManager,
  ledgerApiUrl: process.env.CANTON_API_URL ?? 'http://localhost:7575',
});

// Creates POST /login, POST /logout, GET /session, GET /refresh handlers in one call.
// sandboxProvision: true automatically allocates a Canton party on first login.
export const authHandler = createAuthHandler({
  nexusServer: nexus,
  session: sessionManager,
  sandboxProvision: true,
});
```

Mount both handlers in your router:

## Step 2 — Register your Daml types once

This is the most important step. You import your Daml generated types, put them in a single object, and pass that object to the client. After this, you never write a templateId string or a generic type parameter again — anywhere in your app.

```ts title="lib/nexus-types.ts"
import {
  CollateralHolding,
  MarginCall,
  RoutingSuggestion,
  AllocationRecord,
  CollateralPolicy,
  JoinRequest,
  ServiceAgreement,
} from '@daml.js/nexus-example-0.0.1/lib/CollateralRouter';

// This object is the plugin — pass it directly to createNexusClient below.
export const nexusTypes = {
  CollateralHolding,
  MarginCall,
  RoutingSuggestion,
  AllocationRecord,
  CollateralPolicy,
  JoinRequest,
  ServiceAgreement,
};
```

When you add a new Daml template, you add one line here. That's the only place you ever touch to register a new template.

## Step 3 — Create the browser client

```ts title="lib/nexus-client.ts"
import { createNexusClient, authPlugin, tanstackQueryPlugin } from '@nexus-framework/react';
import { nexusTypes } from './nexus-types';

export const nexus = createNexusClient({
  baseUrl: '/api/ledger',
  plugins: [
    // Reads the session cookie and attaches the Canton token to every request.
    // The token never lives in the browser bundle.
    authPlugin({ basePath: '/api/nexus-auth' }),

    // Adds useContracts, useCreateContract, useExerciseChoice, and all other hooks.
    tanstackQueryPlugin(),

    // Unlocks nexus.types.CollateralHolding.useContracts() and all typed namespaces.
    nexusTypes,
  ],
});
```

Add the provider to your app root:

## Step 4 — Query the ledger

Every component in your app can now read Canton contracts with a single hook call. The payload type comes from your Daml codegen — TypeScript knows exactly what fields exist, and will error at compile time if a field is missing or renamed.

```tsx title="components/Dashboard.tsx"
import { nexus } from '@/lib/nexus-client';

export function Dashboard() {
  const { data: holdings, isLoading } = nexus.types.CollateralHolding.useContracts();
  const { data: calls } = nexus.types.MarginCall.useContracts();

  if (isLoading) return <p>Loading…</p>;

  return (
    <div>
      <section>
        <h2>Holdings ({holdings?.contracts.length ?? 0})</h2>
        {holdings?.contracts.map((c) => (
          // c.payload is fully typed from Daml codegen — no casting needed
          <div key={c.contractId}>
            {c.payload.assetId} — {c.payload.quantity} {c.payload.currency}
          </div>
        ))}
      </section>

      <section>
        <h2>Pending Margin Calls ({calls?.contracts.length ?? 0})</h2>
        {calls?.contracts.map((c) => (
          <div key={c.contractId}>
            {c.payload.callAmount} {c.payload.currency} due {c.payload.dueDate}
          </div>
        ))}
      </section>
    </div>
  );
}
```

## Step 5 — Write to the ledger

Mutations follow the same pattern. The choice argument type and the Daml return value type are both inferred:

```tsx title="components/ApproveButton.tsx"
import { nexus } from '@/lib/nexus-client';

export function ApproveButton({ contractId, partyId }: Props) {
  const { mutate, isPending } = nexus.types.RoutingSuggestion.useExercise('ApproveSuggestion');

  return (
    <button
      disabled={isPending}
      onClick={() => mutate({ contractId, choiceArgument: {}, actAs: [partyId] })}
    >
      {isPending ? 'Approving…' : 'Approve'}
    </button>
  );
}
```

When the mutation succeeds, the caches for `RoutingSuggestion` and `AllocationRecord` are automatically invalidated and refetched. You do not need to call `invalidateQueries` anywhere.

<Callout type="info">
  **Environment setup:** Add `SESSION_ENCRYPTION_KEY` to your `.env`. Generate the value with:
  `bun -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

  Bun loads `.env` automatically — no dotenv package needed.
</Callout>
